Источник — [Figma, Adaptive / 768, 4209:32851](https://www.figma.com/design/aVwbPxZ5FUxYkvTcvME566/?node-id=4209-32851). Проверено содержимое от hero до формы вопроса; шапка и подвал исключены из исправлений. Остальные ширины проверены на регрессии, без нового аудита их дизайна.

## Данные и метод

В рабочей копии отсутствовал кэш прежних проверок. Получены подробные `get_design_context` девяти секций, точные свойства значимых дочерних узлов через чтение Plugin API и скриншоты секций и всей страницы в натуральном масштабе 768 px. Общий запрос страницы вернул sparse-дерево: оно использовано только как индекс, а не для назначения стилей.

- Кэш: `figma/index.json`, `figma/context.json`, `figma/audit-768/`; подробные свойства — `figma/audit-768/properties.json`.
- Проверяемые исходные значения с ID узлов — `audit-768.json`; 72 элемента, геометрия и типографика.
- До исправлений: `screenshots/abiturient/audit-768/before/`; после: `after/`.
- Сравнения: `screenshots/abiturient/audit-768/comparisons/1.png` … `9.png`, слева Figma, справа браузер. Снимки внутренних контейнеров центрированы с полями соответствующего кадра.
- Точные значения Figma сохранены до округления. CSS использует целые пиксели; координаты внутренних элементов проверяются относительно своей секции, внешние интервалы — отдельно. Разница до 2 px может накапливаться при независимом округлении контактных кнопок и соседних секций.

## Воспроизведение проверок

После `pnpm build` запустить `pnpm preview --host 127.0.0.1 --port 4173`, затем:

```sh
node tools/check-abiturient-768.mjs
node tools/check-abiturient-tablets.mjs
node tools/audit-abiturient-768.mjs after
```

Для новой задачи исходное состояние сохраняется до правок командой `node tools/audit-abiturient-768.mjs before`; не перезаписывать исходную базу текущей проверки после исправлений.

- Сборка и проверка данных проекта проходят; проверка форматирования четырёх изменённых SCSS проходит.
- Проверка 72 элементов по Figma проходит; результат — `screenshots/abiturient/audit-768/node-comparison.json`.
- Проверены 33 ширины: все десять точек `_vars.scss`, границы ±1 px, а также 820, 1024 и 1920 px. Нет переполнения и ошибок загрузки. Размеры секций на ширинах вне 577–768 px сохранены относительно исходного состояния.
- HTML и размеры шапки/подвала сохранены на всех 33 ширинах; PNG шапки и подвала на 768 px совпадают с исходными побайтово.
- Планшетная проверка геометрии секций 768, размеров карточек 992/768, вкладок с клавиатуры, сохранения FAQ, слайдера и валидации формы проходит. Точная геометрия всего 992 здесь не утверждается.

## Ограничения и существующие замечания

- Общий `check-abiturient.mjs` останавливается на прежней высоте контактов 1920: исходная и итоговая высоты 782 px при ожидании 778 px. Общая проверка семи макетов `check-abiturient-alignment.mjs` также содержит прежние расхождения вне 768; соседние макеты в этой задаче не исправлялись. Регрессии проверены отдельной исходной базой.
- Общий `format:styles:check` сообщает о 28 нетронутых SCSS/UI-файлах. Массовое форматирование, включая шапку/подвал, не выполнялось. Существующие предупреждения Vite о classic defer-скриптах сохраняются.
- Групповой экспорт студентов `4231:41714` непрозрачен: alpha min=max=255. Он сохранён только как диагностический материал; в коде оставлен прозрачный локальный ресурс. Фон вручную не удалялся. Пустой декоративный слой `Ellipse 469` не использован: видимый маркер получен из `Ellipse 467`.
- Сохранены существующие тексты отзывов и ответов FAQ: отдельные дизайнерские демонстрационные формулировки отличаются. Возможны различия растеризации шрифтов Figma/Chrome и нативный маркер изменения размера textarea. Полное попиксельное совпадение всей страницы не заявляется.
- PHP, сервер, импорт в Битрикс, другие страницы, Git staging/commit/push и деплой не затрагивались.
