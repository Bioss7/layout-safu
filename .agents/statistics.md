# Учёт журналов и токенов по запросу

Применять только при прямом запросе пользователя на учёт или обновление статистики.
Для обычной разработки регистрация журнала и переключение этапов не обязательны.
Команды выполнять внутри layout-safu/.

- Зарегистрировать только журнал текущего чата: `node tools/ai-statistics.mjs --register <путь-к-jsonl> --page <page>`. Старые и чужие сессии не сканировать.
- Пути остаются в игнорируемой .ai-statistics/; браузер получает только агрегаты. Если журнал недоступен, сообщить об этом, данные не выдумывать.
- Для зарегистрированного журнала отмечать начало реализации через `node tools/ai-statistics.mjs --phase implementation`, начало проверок — через `node tools/ai-statistics.mjs --phase verification`.
- В конце обновить отчёт: `node tools/ai-statistics.mjs`. Планирование определяется режимом Plan журнала, неизвестный этап остаётся неизвестным. Финальная реплика попадёт при следующем обновлении.
- В /ui/statistics/ кнопка обновляет отчёт локальным сборщиком без модели/MCP.
- Токены, вызовы MCP и лимит аккаунта различаются. Кэш входит во входные токены, reasoning — в выходные; повторно не суммировать. Расход отдельных MCP-вызовов не выдумывать.
- Лимит аккаунта показывать только как датированный снимок источника, иначе — «Нет данных».
- Источник агрегатов — игнорируемый .ai-statistics/report.json. HTML не рассчитывает расход из Markdown. Счётчики блоков поступают из ui/data/blocks.json.
- Фильтры не должны выдавать неподтверждённые дату или этап за нулевое количество.
- При изменении механизма статистики проверить `pnpm check:statistics`; при изменении проектных данных — `pnpm project:data:check` и `pnpm check:project-data`.
- Сырые журналы, переписку, команды, секреты и абсолютные пути журналов не публиковать и не добавлять в репозиторий. Служебный UI, отчёты и кэш Figma не импортировать в Битрикс.
