# Данные макета и ресурсы

При самостоятельной работе один агент может получать данные Figma и реализовывать
изменения. При делегировании аналитик изменяет только назначенные кэш и ресурсы,
а ссылки на результаты и недостающие данные передаёт координатору.

## Контекст и кэш

1. Проверить требования, локальный код, public/<page>/assets/ и пригодный кэш <page>/figma/: индекс node ID, context.json, скриншоты и токены.
2. Для изменяемых свойств и зависимостей блока составить в кэше краткий перечень «узел/параметр — подтверждено — отсутствует/устарело». Исследовать дочерние элементы полностью, если изменение затрагивает их геометрию или оформление; не собирать несвязанные свойства ради полноты дерева.
3. Получить только недостающие или подтверждённо устаревшие данные. До MCP сообщить инструменты, узлы и цель запроса; до get_design_context использовать доступный `figma-design-to-code`. Для визуальной реализации нужны подробные данные изменяемых свойств и эталонный скриншот соответствующего кадра. Если ответ усечён или разрежен, запросить нужные дочерние узлы. Точные свойства также допустимо получить чтением Plugin API после загрузки `figma-use`. Пригодные данные повторно не запрашивать сверх требований применяемого навыка.
4. Сохранить источники до изменения кода: в <page>/figma/index.json — fileKey, node ID, назначение, брейкпоинт, локальный файл и дату; в context.json — повторно используемые данные с источником каждого измерения и шириной кадра. Сохранить эталоны предусмотренных задачей кадров и состояний, точные значения — до округления в SCSS. При делегировании передать ссылки исполнителям.
5. Выполнить изменение по подтверждённым данным. При конфликте источников указать узел и параметр; существенную неустранимую нехватку данных сообщить пользователю. Не подставлять предполагаемые значения молча; не придумывать иконки, типографику и отсутствующие состояния.

Для затронутых свойств проверять размеры и координаты, Auto Layout, padding/gap,
выравнивание, типографику, заливки, рамки, эффекты, геометрию и обрезку ресурсов.
Для затронутых блоков подтвердить также интервалы между соседними блоками,
а для текста — семейство, начертание, размер, line-height, letter-spacing,
регистр, ширину текстового блока и переносы на соответствующих кадрах.
Одного общего дерева или внешних границ недостаточно для проверки внутреннего оформления.
Отделять свойства Figma от оценок по скриншоту и вычислений для HTML-обёрток;
вычисленный margin не называть свойством макета. Не выдавать оценки за точные измерения.
Неприменимые свойства отмечать в перечне, если они важны для объяснения решения.

Переводить геометрию Figma в CSS с учётом box-sizing, рамок, внутренних обёрток
и теней; проверять итоговое положение содержимого в браузере. Не копировать
числа и не вычитать толщину рамки автоматически без расчёта конкретного элемента.

Соотносить ширину кадра с переменной `_vars.scss`, учитывая включительную границу
max-width. Не переносить геометрию одного кадра на другой и не добавлять брейкпоинты
без разрешения. Документ Figma без разрешения не менять; если изменение разрешено,
до Plugin API использовать доступный навык `figma-use`.

## Экспорт

- До экспорта проверить готовые локальные файлы, кэш и сгруппированные композиции нужного кадра. Пригодный файл использовать повторно.
- Людей, карты и художественные композиции экспортировать родительской группой целиком, с корректной прозрачностью. Проверить пересечения соседних слоёв; текст и интерактивные элементы не превращать в картинку.
- При отличающейся композиции или пропорциях экспортировать нужный вариант брейкпоинта. При неизменной композиции достаточно масштабирования. Карты городов брать из готовых вариантов макета.
- Имена — английский нижний регистр: hero-people-390.png, hero-bg-1440.png, map-arkhangelsk.png, icon-question.svg; фотографии — 01, 02, 03. Суффикс обозначает брейкпоинт, не плотность пикселей.
- Место ресурсов: public/<page>/assets/img/<block>/. Иконки брать из соответствующего узла Figma либо использовать подтверждённый идентичный локальный ресурс. Не заменять символами, эмодзи, похожими библиотечными иконками или придуманными SVG. Загрузка файла и подходящее имя сами по себе не подтверждают соответствие рисунка макету.
- Временные URL скачать в локальные файлы; в коде использовать постоянные локальные пути. Проверить формат, непустое содержимое, пропорции и назначение.
- При сбое экспорта сначала проверить готовые варианты и настройки. Не запускать массовые повторные запросы и не скачивать дерево страницы ради одного изображения.
- В итогах назвать причины дополнительных запросов. Расход токенов без источника не оценивать.

Визуальную проверку результата выполнять по [interface-review](../interface-review/SKILL.md).
