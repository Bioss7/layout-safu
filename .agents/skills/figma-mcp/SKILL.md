# Данные макета и ресурсы

## Источники и кэш

1. Проверить требования, локальный код, public/<page>/assets/ и кэш <page>/figma/. Для изменяемых свойств и зависимостей отметить: узел/параметр — подтверждено, отсутствует или устарело. Собирать данные только в пределах задачи.
2. Для каждого используемого кадра и состояния указать в index.json действующий источник: fileKey, node ID, ширину кадра, состояние, назначение, локальный файл и дату получения. При замене пометить прежнюю запись как заменённую со ссылкой на действующую. Имя current и более поздняя дата сами по себе не подтверждают актуальность: сверить идентификаторы и назначение. При неразрешённом конфликте источник считать неподтверждённым.
3. Получить недостающие или устаревшие данные и эталонный скриншот нужного кадра/состояния. До MCP назвать инструменты, узлы и цель; до get_design_context использовать доступный `figma-design-to-code`, до чтения Plugin API — `figma-use`. При усечённом или разреженном ответе запросить нужных детей и родителя, а не всё дерево страницы. Повторные запросы — по корневым правилам и требованиям применяемого навыка.
4. До изменения кода сохранить повторно используемые данные в context.json или профильном файле кэша со ссылкой из индекса. У каждого измерения сохранять источник, способ получения и исходное значение без округления; у координат — систему отсчёта. Сохранить соответствующие эталоны кадров и состояний.

Различать три вида данных:

- **Свойства узлов Figma:** непосредственно прочитанные размеры, координаты, Auto Layout, типографика и оформление с node ID. Это источник числовых измерений.
- **Сгенерированное представление MCP:** код и его CSS-значения — вспомогательный контекст. Реализовывать классической вёрсткой по правилам проекта. Спорные значения подтверждать непосредственным чтением свойств узла.
- **Вычисления для CSS:** относительные координаты, интервалы и поправки для HTML-обёрток. Сохранять исходные узлы и расчёт; вычисленный margin не называть свойством Figma. Оценки по скриншоту отмечать отдельно, не выдавать за точные измерения.

При несовпадении чисел и изображения проверить нужный узел и родителя:
локальные/абсолютные координаты и трансформации, размеры раскладки и видимой
области с эффектами, обводку и её положение, обрезку, Auto Layout и выравнивание.
Подтверждать затронутых детей и интервалы между блоками; внешних границ недостаточно.
Для текста получать параметры оформления и ширину блока, необходимые для проверки
переносов. Если конфликт остаётся, указать узел, параметр и недостающие данные;
не выбирать значение молча и не придумывать дизайн или существенное поведение.

Переводить геометрию в CSS с учётом box-sizing, обводок и HTML-обёрток;
толщину рамки не вычитать автоматически. Правила дробных значений и брейкпоинтов —
в [scss-architecture](../scss-architecture/SKILL.md). Геометрию одного кадра
не переносить на другой. Документ Figma без разрешения не менять.

## Экспорт

- Проверить локальные файлы и кэш; пригодный ресурс использовать повторно. Иконки брать из нужного узла или подтверждённого идентичного файла, без замены символами, эмодзи, похожими иконками или придуманными SVG.
- Людей, карты и художественные композиции экспортировать родительской группой с корректной прозрачностью; проверить пересечения соседних слоёв. Текст и интерактивные элементы оставлять разметкой. При другой композиции/пропорциях брать вариант соответствующего кадра, при неизменной — масштабировать. Карты городов брать из готовых вариантов макета.
- В кэше указывать узел, масштаб и параметры экспорта, размеры файла и границы содержимого/эффектов. Размер PNG при масштабе 2 не равен размеру CSS. При артефакте проверить прозрачные поля, обрезку, маски, пересечения и включённые тени по эталону; при сбое сначала проверить настройки и готовые варианты.
- Ресурсы хранить в public/<page>/assets/img/<block>/. Имена — английский нижний регистр: hero-people-390.png, map-arkhangelsk.png, icon-question.svg; фотографии — 01, 02, 03. Суффикс ширины обозначает брейкпоинт, не плотность пикселей.
- Временные URL скачивать локально; в коде использовать постоянные пути. Проверять формат, непустое содержимое, пропорции и соответствие рисунка исходному узлу; имя файла соответствия не доказывает.

Проверка реализации и отчёт — по [interface-review](../interface-review/SKILL.md).
