# Данные макета и ресурсы

Работу выполняет назначенный аналитик Figma либо координатор.
Аналитик изменяет кэш и ресурсы назначенной страницы, но не её код.

## Контекст и кэш

1. Проверить требования, локальный код, public/<page>/assets/ и <page>/figma/: индекс node ID, context.json, скриншоты и токены.
2. Составить краткий перечень «узел/параметр — подтверждено — отсутствует/устарело». До MCP сообщить инструменты, узлы и цель запроса.
3. Для реализации применять доступный `figma-design-to-code` до get_design_context. Нужны контекст и скриншот соответствующего кадра; одних разреженных метаданных недостаточно. Не повторять запросы уже пригодных данных сверх требований этого навыка.
4. Запрашивать только недостающие или подтверждённо устаревшие данные. При усечённом ответе или разреженных метаданных найти нужные дочерние узлы и запросить их, а не все брейкпоинты страницы.
5. Сохранить данные и передать исполнителям ссылки на кэш. При конфликте источников указать конкретный узел и параметр; неизвестные значения точными не объявлять.

### Полнота данных перед исправлением блока

- Для каждого проверяемого блока и значимых дочерних элементов сохранить подробный `get_design_context` и эталонный скриншот. Общее дерево страницы, сокращённый ответ или снимок без измерений не считаются полным контекстом.
- До правок составить в кэше перечень «узел/параметр — подтверждён — отсутствует». Проверить размеры и координаты, Auto Layout, padding, gap, выравнивание, типографику, заливки, рамки, эффекты, геометрию и обрезку ресурсов. Margin HTML-обёрток вычислять отдельно: в Figma такого свойства может не быть.
- При усечении или sparse-ответе запрашивать нужные дочерние узлы до получения всех параметров исправляемого блока. Точные свойства, отсутствующие в контексте, допустимо получить чтением Plugin API после загрузки `figma-use`; документ не изменять.
- Сначала проверить и использовать пригодный кэш; MCP вызывать только для отсутствующих или подтверждённо устаревших данных. Сохранять результаты до исправления кода, включая ID узлов, дату, ширину кадра и источник каждого измерения. Не повторять запрос ради уже сохранённого пригодного значения.
- Соотносить ширину кадра с переменной `_vars.scss`; учитывать включительную границу `max-width`. Не переносить геометрию одного кадра на другой и не добавлять брейкпоинты без разрешения.
- Не подменять отсутствующее значение оценкой по скриншоту. Необязательные и неприменимые свойства явно отмечать; существенную неустранимую нехватку данных сообщать пользователю.

В <page>/figma/index.json фиксировать fileKey, node ID, назначение, брейкпоинт,
локальный файл и дату. context.json хранит повторно используемые данные.
Сохранять эталоны 1920/390 и других предусмотренных задачей кадров и состояний.

Измерения включают координаты и размеры блоков и дочерних элементов, padding,
margin, gap, семейство/начертание/размер текста, line-height, letter-spacing
и внутреннюю геометрию SVG. Отделять свойства Dev Mode от оценок по скриншоту
и вычислений для HTML-обёрток. Точные исходные значения сохранять до округления в SCSS.

Не придумывать иконки, типографику и отсутствующие состояния. Недостающие данные
сообщать координатору с указанием блока. Документ Figma без разрешения не менять;
если изменение разрешено, до Plugin API использовать доступный навык figma-use.

## Экспорт

- До экспорта проверить готовые локальные файлы, кэш и сгруппированные композиции нужного кадра. Пригодный файл использовать повторно.
- Людей, карты и художественные композиции экспортировать родительской группой целиком, с корректной прозрачностью. Проверить пересечения соседних слоёв; текст и интерактивные элементы не превращать в картинку.
- При отличающейся композиции или пропорциях экспортировать нужный вариант брейкпоинта. При неизменной композиции достаточно масштабирования. Карты городов брать из готовых вариантов макета.
- Имена — английский нижний регистр: hero-people-390.png, hero-bg-1440.png, map-arkhangelsk.png, icon-question.svg; фотографии — 01, 02, 03. Суффикс обозначает брейкпоинт, не плотность пикселей.
- Место ресурсов: public/<page>/assets/img/<block>/. Иконки — точные предоставленные SVG или подтверждённые экспорты; похожими символами или придуманными контурами не заменять.
- Временные URL скачать в локальные файлы; в коде использовать постоянные локальные пути. Проверить формат, непустое содержимое, пропорции и назначение.
- При сбое экспорта сначала проверить готовые варианты и настройки. Не запускать массовые повторные запросы и не скачивать дерево страницы ради одного изображения.
- В итогах назвать причины дополнительных запросов. Расход токенов без источника не оценивать.

Визуальную проверку результата выполнять по [interface-review](../interface-review/SKILL.md).
