# Работа с Figma MCP — экономия запросов и токенов

Цель: получить нужное один раз и больше к макету не возвращаться. Каждый лишний запрос — реальные токены (особенно изображения).

## Обязательно перед любым вызовом

Одна строка формата: `Figma: <инструмент> → <node-id/фрейм> — зачем`. Без этой строки не вызывать. Если инструментов несколько — называть план на всю группу, а не по одному на сообщение.

## Порядок обращений (от дешёвого к дорогому)

1. **Локальный код.** Прежде чем лезть в Figma — grep по `_vars.scss` и существующим блокам: токены и типовые размеры уже там. Нет нужных значений в проекте — только тогда Figma.
2. **node-id.** Попросить пользователя сразу дать URL фрейма с `node-id=` (или конкретные id узлов). Это бесплатно и заменяет навигацию по файлу.
3. **get_metadata** — только если id неизвестен. Один запрос для локализации нужного фрейма, не для всего файла.
4. **get_variable_defs** — один раз на файл/страницу: выгружает дизайн-токены целиком. Результат сразу превратить в `:root`-переменные в `src/scss/_vars.scss` — это и есть кэш, повторно не запрашивать.
5. **get_code** — строго на один фрейм/секцию, не на всю страницу и не на файл. Если нужна одна карточка — запрашивать узел карточки.
6. **get_image / скриншот** — только если без визуала нельзя (сравнить композицию, прочитать картинку-иллюстрацию). Один визуал на секцию максимум; никогда не скриншить поэлементно. Изображения тратят кратно больше токенов, чем код.

## Правила после получения ответа

- Сразу зафиксировать результат в проекте: цвета/шрифты → `_vars.scss`, размеры/отступы → в код блока. «Потом вернусь» = второй запрос = брак по токенам.
- Повторный вопрос о том же узле в рамках сессии запрещён — смотреть то, что уже записано (файлы проекта или собственный предыдущий ответ).
- Из ответа брать только нужное: не копировать весь CSS-вывод в сообщение, оставлять релевантный фрагмент.

## Запреты

- Не исследовать макет «просто посмотреть» — только по явной задаче.
- Не выгружать целиком страницу/файл, если хватает одного фрейма.
- Не перебирать инструменты по одному в разных сообщениях — сначала собрать план запросов, выполнить пачкой.
- Не запрашивать изображение вместо кода, если нужны значения (цвет, отступ, шрифт).
- Если сервер вернул огромный ответ — сузить узел и повторить один раз, а не читать дамп целиком.

## Итог обращения

После работы с Figma — 2–3 строки: что взято, куда записано. Если что-то не удалось получить — написать об этом, а не пробовать пять разных способов.
