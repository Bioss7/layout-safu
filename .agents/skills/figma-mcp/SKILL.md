# Сначала локальный кэш

Проверить <page>/figma/, индекс node ID, context.json, токены и код. Перед MCP написать «Figma: <инструменты> → <узлы> — зачем». Запрашивать только недостающие данные/экспорты или подтверждённые изменения. Не повторять выгрузку всего файла.

Для реализации следовать официальному figma-design-to-code: высокоточный контекст и скриншот; sparse metadata недостаточно. Результат переводить в проектный стек. Для Plugin API сначала figma-use; без разрешения документ не менять.

## Группы и ресурсы

- Найти родительский узел: люди, художественная композиция, карта экспортируются целиком с корректной прозрачностью. Не выгружать каждый декоративный слой и не пересобирать CSS-координатами.
- При изменении композиции или пропорций на любом брейкпоинте использовать подходящий отдельный групповой экспорт через picture/source media. Суффикс имени указывает брейкпоинт, например hero-people-1440.png или hero-bg-1440.png, а не плотность пикселей. Размеры и пропорции выбранного варианта сохранять. Если промежуточного варианта нет, проверить локальный кэш и требования; не выдавать самостоятельно придуманную композицию за макет. Обычное масштабирование при неизменной композиции не требует отдельного экспорта на каждой точке. Карты городов — готовые варианты макета.
- Интерактивный текст/формы/кнопки оставлять разметкой. При экспорте проверить пересекающиеся соседние слои.
- Иконки точно из макета с осмысленными именами; одноцветные SVG использовать масками.
- Папка public/<page>/assets/img/<block>/. Английский нижний регистр: hero-bg-1920.png, hero-people-390.png, map-arkhangelsk.png, icon-question.svg, icon-vk.svg, icon-max.svg. Серии фотографий — 01,02,03.
- Временные URL сразу скачать и заменить локальными. Проверить формат, непустой файл, пропорции и слот.

## Эталоны

В <page>/figma/ сохранять скриншоты 1920/390 и состояния. index.json содержит fileKey, node ID, назначение, локальный файл и дату; context.json — повторно используемые данные. Временный URL не является постоянным источником.

Реализация — отдельно screenshots/<page>/. Повторные MCP нужны лишь при нехватке/устаревании данных. Итог сообщает причины дополнительных обращений; токены без данных источника не оценивать.

## Достоверность оформления

- Иконки — только точные предоставленные пользователем SVG, подтверждённые локальные экспорты или экспорты Figma. Не использовать символы, похожие изображения и придуманные контуры. При недоступном ресурсе сообщить в чате конкретный блок, иконку и причину; не скрывать проблему заменой.
- Типографику и переносы не придумывать. Недостающие параметры и любые обнаруженные расхождения с макетом сообщать в чате, указывая блок; нерешённые фиксировать в реестре замечаний. Сначала локальный кэш, MCP только для конкретных недостающих данных.
