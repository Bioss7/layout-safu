# JavaScript компонентов

- Один файл — компонент или конкретная обязанность: карточки, фильтры, пагинацию и формы не смешивать. HTML подключает каждый обычным script defer; объединяющий page.js не использовать.
- Компонент сам инициализируется после готовности DOM. Отсутствие его разметки не вызывает ошибку. Не создавать глобальные авторские переменные и повторные обработчики.
- Итоговые скрипты самодостаточны, без import/export и неявных общих чанков; каталог <page>/assets/js/ определяет принадлежность странице. Общие скрипты — assets/js/, библиотеки — assets/vendor/. Локальный сторонний скрипт подключается перед зависимым компонентом, лицензия сохраняется.
- Небольшие явные функции, понятные имена, читаемый код. Нетривиальную логику и ограничения объяснять русскими комментариями; лицензии стороннего кода не переводить. Это относится и к авторским тестам.
- Предпочитать простые последовательные действия и явные условия. Избегать вложенных тернарных операторов, плотных однострочных выражений и абстракций без необходимости; сложную цепочку операций разбивать на понятные шаги.
- Обработчики — на js-* с поиском внутри компонента; data-* — настройки и ключи. Состояние синхронизировать через БЭМ, hidden и aria-*.
- DOM-хуки именовать через дефис: `js-<component>-<role>`, без camelCase и подчёркиваний. Перед добавлением проверить хуки подходящего готового компонента. Для одинаковых компонентов и ролей сохранять одинаковые имена на всех новых и адаптируемых страницах, включая select; страничные префиксы для одного поведения не вводить. Разные сценарии select не объединять только из-за одинакового типа элемента. Старые страницы вне задачи не переименовывать.
- Геометрию задавать CSS. JS допустим для scrollLeft/scrollTop и определения доступного места списка с русским пояснением.
- Клавиатура, фокус, Escape и aria-состояния должны работать согласованно. Неочевидное действие уточнять по требованиям, макету и коду; демонстрацию не выдавать за реальную отправку.
- Для drag-scroll использовать Pointer Events и scrollLeft; touch оставлять нативным. При drag — grabbing, после него подавлять случайный click, сохраняя обычный click и клавиатуру.
- Поля проверяют необходимые ограничения, сообщения связаны через aria-describedby. Без согласованного обработчика данные не отправлять и не сохранять.
- На страницах с формами адаптировать меню проверки из `events/index.html` (`demo-menu-anchor`, `demo-menu`, `js-demo-menu`) вместе с необходимыми стилями и поведением. Меню должно переключать применимые состояния формы: пустая, заполненная, открытый select, ошибки полей, отправка, успех, ошибка отправки и повтор. Учитывать несколько форм, если они есть. Демонстрация явно обозначена, не выполняет сетевую отправку и не сохраняет введённые данные; исходную страницу `events` не менять.
- При проверке учитывать длинные значения, переполнение, pointercancel и смену ширины; общая процедура — [interface-review](../interface-review/SKILL.md).
