# Разметка компонентов

Зона верстальщика — HTML назначенной страницы. Компонент включает разметку,
свой <page>/assets/scss/blocks/<block>.scss и при необходимости отдельный JS в <page>/assets/js/. Общая оболочка шаблона хранится в корневом assets/.
Перед созданием проверить каталог ui/data/blocks.json по [правилам проекта](../../project.md#реестры).
Копировать аналог вместе с ресурсами в текущую страницу, адаптировать только копию.

- Семантика: один h1, последовательные h2/h3; main/nav/section/article и списки — по назначению. div/span — нейтральные обёртки.
- Переход — a с href, действие — button с явным type, отправка данных — form. Без кликабельных div и вложенного интерактива; неизвестный адрес или результат действия не заменять демонстрационным диалогом.
- Если ссылка предусмотрена макетом, но адрес неизвестен, ставить `href="#"`. Сохранять семантику ссылки, доступность с клавиатуры и предусмотренные hover/focus-состояния; не подменять её span/article с role="link" или aria-disabled. Disabled применять только к действительно недоступному элементу по требованиям/макету. Кнопки действий и вкладки не превращать в ссылки.
- БЭМ: block, block__element, block--modifier. Базовый класс и модификатор сохранять вместе в HTML. CSS-правила — в [scss-architecture](../scss-architecture/SKILL.md).
- Общий контейнер оформлять классом `.container`; отличия конкретной страницы — модификатором, например `.container--student`. В HTML использовать `class="container container--student"`, в SCSS оставлять общую базу в `.container`, а в модификаторе — только необходимые отличия. Не создавать параллельные блоки `.student-container` и подобные.
- Для обработчиков предусмотреть js-*; data-* — ключи и настройки, БЭМ-модификаторы — состояние. Контракт согласовать со специалистом JavaScript до параллельных правок.
- У иконок-кнопок — aria-label; у вкладок и аккордеонов — связанные aria-состояния. У декоративных изображений — пустой alt.

## Изображения

- Для одного варианта изображения использовать img с подходящим alt, width и height. Для разных вариантов по медиазапросам использовать picture с source/media и резервным img с этими атрибутами. Декоративные фоны и маски — в CSS.
- При изменении композиции или пропорций подключать подходящий вариант через source/media и сохранять пропорции. При неизменной композиции достаточно масштабирования; отдельный ресурс для каждой ширины не нужен.
- Художественные группы получать целиком по [figma-mcp](../figma-mcp/SKILL.md), не пересобирать из декоративных слоёв. Интерактивный текст, формы и кнопки оставлять разметкой.
