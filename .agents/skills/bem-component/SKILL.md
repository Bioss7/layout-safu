# Компоненты страницы

Компонент = разметка + свой src/scss/<page>/blocks/<block>.scss + при необходимости src/js/<page>/<block>.js. SCSS подключается через @use в style.scss, JS — отдельными <script defer> для каждого компонента. Другие страницы не являются runtime-зависимостями.

- Раскладки только Flexbox: flex-wrap, flex-basis, min-width:0, gap. Без display:grid/inline-grid/grid-* и названий *-grid.
- БЭМ: .block, .block__element, .block--modifier. Элементы — плоские селекторы; детали в [scss-architecture](../scss-architecture/SKILL.md).
- Отступы секций — padding, согласованный между соседями. Внутренние ряды используют gap.
- Изображения — picture с обязательным img/alt/width/height. Если на брейкпоинте меняются пропорции или композиция, использовать отдельный подходящий вариант через source/media, сохраняя его пропорции, а не растягивать исходник. Суффикс имени — ширина брейкпоинта, например hero-people-1440.png; для фона — hero-bg-1440.png. При одинаковой композиции достаточно резинового масштабирования; варианты только ради каждой точки не создавать. Одиночное изображение тоже внутри picture. Декоративные фоны/маски — CSS.
- Статические художественные группы экспортировать целиком: не пересобирать людей, карты и иллюстрации из слоёв. Интерактивный текст/формы не превращать в картинку.
- Семантическая HTML-вёрстка обязательна: один h1, последовательные h2/h3, main/nav/section/article и списки — по смыслу содержимого. Кнопки button — для действий, ссылки a с адресом — для переходов; div/span — для нейтральных обёрток. Не заменять ссылки кнопками или кликабельными div; без вложенного интерактива. Если адрес или действие неизвестны, уточнить у пользователя; не придумывать диалог вместо перехода.
- У иконок-кнопок aria-label, у вкладок/аккордеонов синхронизированные aria-состояния. Декор — пустой alt.
- Обработчики используют js-*, data-* — ключи и настройки, БЭМ-модификаторы — состояние.
- Не угадывать существенное поведение: требования/макет/код, затем вопрос пользователю при оставшейся неоднозначности.

## Переиспользование и поведение

- Перед созданием блока читать ui/data/blocks.json: entries и reusableComponents. Найти подходящий аналог и изучить указанные HTML/SCSS/JS. Копировать разметку, стили, ресурсы и необходимый JS в текущую страницу, затем адаптировать только копии; не подключать ресурсы другой страницы напрямую.
- Реестр дополнять назначением, относительными путями исходников и ссылкой на подтверждённый аналог. Описание и примеры переиспользования не являются новыми блоками для статистики. Проверенный набор аналогов не означает полную инвентаризацию страницы.
- Переход оформлять a с href, действие и отправку формы — button с явным type. Форму оформлять form, статичную обёртку — подходящим семантическим тегом или div. Не превращать форму целиком в кнопку.
- Если результат действия неочевиден, проверить требования, макет и код, затем спросить пользователя до реализации поведения. Не подменять переход демонстрационным диалогом.
