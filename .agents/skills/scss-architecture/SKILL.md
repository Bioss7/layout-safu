# SCSS-архитектура (layout-safu)

Правила устройства стилей поверх правил БЭМ из `bem-component`. Уточняют только структуру SCSS-файлов.

## Структура файлов

- Единственная точка входа — `src/scss/style.scss`, компилируется через `@use`.
- Каждый блок — `src/scss/blocks/<block>.scss` и начинается с:

  ```scss
  @use "../_mixins" as *;
  @use "../_vars" as *;
  ```

- Новый блок подключается в `style.scss` в конец списка: `@use "blocks/<block>";`
- `_vars.scss` (токены) НЕ менять при рефакторинге — только использовать `var(--main-*)`.
- Типовые общие элементы (`.section-header`, `.link-arrow`, `.arrow-btn`, `.slider-dots`) — в едином `blocks/common.scss`. Типографика (`.title-2`, `.section-descr`, `.section-header__descr`) — в `blocks/typography.scss`.

## Вложенность — только модификаторы и псевдоклассы

- Элементы выносить из блока на верхний уровень: `.block__element`, а не `&__element`.

  ```scss
  // плохо
  .card {
    &__title { … }
  }

  // хорошо
  .card { … }          // только сам блок
  .card__title { … }   // элемент отдельной плоской записью
  ```

- Внутри `.block` и `.block__element` разрешены только:
  - модификаторы `&--active`, `&--primary`, …;
  - псевдоклассы `&:hover`, `&:active`, `&:focus-visible`, `&:disabled`, `&::before`, `&::after`,
    `&:first-child`, `&:not(&--active)` и т.п.

  ```scss
  .card__tab {
    &:hover { … }
    &--active { … }
  }
  ```

- Сложные составные селекторы (состояние + элемент) писать полными именами:

  ```scss
  .card--open .card__body,
  .card:hover .card__icon { … }   // вместо &.card--open &__body
  ```

- Правило не касается BEM-элементов/модификаторов: `.card__title--big` — это полноценный класс,
  пишется как `.card__title--big { … }`.
- Внутри `@include breakpoint(...)` та же плоскость: внутри медиа-запроса классы писать полностью, без `&`.

## Дубликаты — удалять

- Один и тот же класс объявляется в файле один раз (все свойства в одном правиле или в одном
  правиле + медиа-запросы внутри него).
- Не дублировать одинаковые декларации в базовых правилах и их модификаторах: модификатор
  меняет только отличие (`color`, `background`), а не повторяет `font-size`/`padding` из базы.
- Не оставлять пустые правила `.foo {}` и пустые `@include breakpoint(...) {}` — удалять.
- Неиспользуемые классы (нет в `index.html` и `src/js/`) — удалять. Проверка: grep по `index.html` + `src/js/`.
- Полностью закомментированные файлы/правила удалять, если их класс не вызывается ни в HTML, ни в JS.

## Соглашения

- Отступ 2 пробела (как остальные блоки), без лишних пустых строк внутри одного правила.
- Скобки и вложенность — только для модификаторов/псевдо-/медиа.
- Валидация — только `pnpm build` (не `pnpm dev`). После рефакторинга запускать сборку обязательно.
- После правок итог: 1–2 строки о том, что изменил.
