# Проверка интерфейса

Проверяющий читает исходники и выполняет разрешённые проверки, но не исправляет код.
Координатор может выполнять эту роль самостоятельно. Проверять изменённые блоки
и затронутые зависимости; не превращать локальную задачу в аудит всех страниц.

## Подготовка

- Получить цель, список изменений, страницы, состояния, ширины и ссылки на подтверждённый кэш. Недостающие измерения передать аналитику Figma или координатору.
- Сверить изменения с профильными правилами HTML, SCSS или JS только для затронутой области.
- Использовать результаты одной согласованной сборки и preview из [project.md](../../project.md#команды). Не запускать сборки параллельно с другими исполнителями. Для ревью существующего результата сначала проверить, актуальна ли сборка.
- Документацию проверять ссылками, структурой и согласованностью правил без сборки интерфейса.

## Сравнение и поведение

- Сравнивать браузер с кадром Figma на одинаковой ширине. Скриншоты реализации хранить отдельно от эталонов: screenshots/<page>/.
- До исправлений сохранить исходные скриншоты страницы и каждого проверяемого блока, браузерные координаты и computed styles. После исправлений повторить снимки страницы и блоков из одной актуальной сборки и сопоставить с подробным кэшем Figma сверху вниз.
- До сверки блока убедиться в полноте контекста по `figma-mcp`: сокращённого дерева или только внешних границ недостаточно. В отчёте связать ожидаемые значения с ID узлов; ожидания тестов не подгонять под реализацию.
- Проверять все существующие точки `_vars.scss`, их границы ±1 px и промежуточные ширины. Точная сверка с макетом относится к кадрам соответствующих ширин; остальные проверки подтверждают адаптивность и отсутствие регрессий, но не выдуманный дизайн.
- Идти по изменённой секции и её дочерним элементам: ширина, высота, координаты, computed padding/margin/gap, типографика, цвет, переносы и пропорции изображений. Совпадение внешних границ секции не заменяет проверку внутренней геометрии.
- Проверять суммирование отступов и накопленный вертикальный сдвиг между секциями. Учитывать округление реализации; видимое расхождение не скрывать сложными субпиксельными формулами.
- Для SVG проверять размер CSS-контейнера и рисунка внутри него, цвет маски и контраст с родителем, включая белую иконку на тёмной карточке. Проверять дублирование и обрезание теней.
- Для HTML-обёртки без узла Figma отдельно фиксировать исходные координаты дочерних узлов, вычисленную корректировку и computed styles. Вычисление не называть отступом из макета.
- Проверять предусмотренные кадры, промежуточные ширины и обе стороны затронутых брейкпоинтов: переполнение, длинные значения, отсутствие горизонтальной прокрутки страницы и неожиданных перестроений. Проверить сохранность шапки и подвала.
- Проверять применимые состояния, клавиатуру, видимый фокус, Escape, aria-*, клики и согласованность hidden. Для форм — ошибки и связь сообщений с полями; отправку с внешним эффектом не выполнять без разрешения.
- Для drag-scroll проверить touch, мышь, pointercancel, отсутствие случайного click после перетаскивания и сохранность обычного click. Для скриптов — отсутствие компонента, повторной инициализации и ошибок консоли.

## Результат

Сообщить проверенные страницы, ширины, состояния и ограничения проверки.
Каждое замечание должно содержать блок/селектор, способ воспроизведения,
ожидаемое и фактическое поведение, источник (node ID/кэш), если он есть.
Открытые расхождения передать владельцу реестра по [правилам проекта](../../project.md#реестры).
Не объявлять непроверенное совпадением и не оценивать неизвестное оформление на глаз.

Повторять проверку после новых правок, ошибки или конкретного оставшегося расхождения;
уже подтверждённые участки без затронувших их изменений повторно не проверять.
