# Проверка интерфейса

Один агент может совмещать реализацию и проверку. При делегировании отдельный
проверяющий читает исходники и выполняет разрешённые проверки, а замечания передаёт
назначенному редактору без самостоятельных правок его файлов. Проверять изменённые
блоки и затронутые зависимости; не превращать локальную задачу в аудит всех страниц.

## Подготовка

- Определить цель, список изменений, страницы, состояния, ширины и ссылки на подтверждённый кэш. Недостающие измерения получить по `figma-mcp`; при делегировании передать запрос аналитику Figma или координатору.
- Сверить изменения с профильными правилами HTML, SCSS или JS только для затронутой области.
- Использовать результаты одной согласованной сборки и preview из [project.md](../../project.md#команды). Не запускать сборки параллельно с другими исполнителями. Для ревью существующего результата сначала проверить, актуальна ли сборка.
- Документацию проверять ссылками, структурой и согласованностью правил без сборки интерфейса.

## Сравнение и поведение

- Сравнивать браузер с кадром Figma на одинаковой ширине. Скриншоты реализации хранить отдельно от эталонов: screenshots/<page>/.
- При исправлении визуальных расхождений до правок сохранить скриншоты затронутых блоков и контекста страницы, координаты и computed styles относящихся к расхождению свойств. После правок повторить снимки и измерения из одной актуальной сборки и сопоставить с кэшем Figma. Для остальных изменений выбирать проверки и снимки по затронутому поведению.
- До сверки блока убедиться, что контекст по `figma-mcp` подтверждает проверяемые свойства и зависимости: одного дерева или внешних границ недостаточно для внутреннего оформления. В отчёте связать ожидаемые значения с ID узлов; ожидания тестов не подгонять под реализацию.
- Для локальных изменений проверять затронутые точки `_vars.scss`, их границы ±1 px, промежуточную ширину между затронутыми точками либо между точкой и соседним диапазоном, а также соответствующие кадры макета. Полный проход по всем точкам и промежуточным ширинам выполнять при изменении общей раскладки или отдельном аудите. Точная сверка с макетом относится к ширинам его кадров; остальные проверки подтверждают адаптивность и отсутствие регрессий.
- Проверять относящиеся к изменению свойства секции и зависимых дочерних элементов: размеры, координаты, computed padding/margin/gap, типографику, цвет, переносы и пропорции изображений. Совпадение внешних границ не заменяет проверку затронутой внутренней геометрии.
- Проверять суммирование отступов и накопленный вертикальный сдвиг между секциями. Учитывать округление реализации; видимое расхождение не скрывать сложными субпиксельными формулами.
- Для SVG проверять размер CSS-контейнера и рисунка внутри него, цвет маски и контраст с родителем, включая белую иконку на тёмной карточке. Проверять дублирование и обрезание теней.
- Для HTML-обёртки без узла Figma отдельно фиксировать исходные координаты дочерних узлов, вычисленную корректировку и computed styles. Вычисление не называть отступом из макета.
- На выбранных ширинах проверять переполнение, длинные значения, отсутствие горизонтальной прокрутки страницы и неожиданных перестроений; при влиянии изменения на шапку или подвал проверить их сохранность.
- Проверять применимые состояния, клавиатуру, видимый фокус, Escape, aria-*, клики и согласованность hidden. Для форм — ошибки и связь сообщений с полями; отправку с внешним эффектом не выполнять без разрешения.
- Для drag-scroll проверить touch, мышь, pointercancel, отсутствие случайного click после перетаскивания и сохранность обычного click. Для скриптов — отсутствие компонента, повторной инициализации и ошибок консоли.

## Результат

Сообщить проверенные страницы, ширины, состояния и ограничения проверки.
Каждое замечание должно содержать блок/селектор, способ воспроизведения,
ожидаемое и фактическое поведение, источник (node ID/кэш), если он есть.
Открытые расхождения передать владельцу реестра по [правилам проекта](../../project.md#реестры).
Не объявлять непроверенное совпадением и не оценивать неизвестное оформление на глаз.

Повторять проверку после новых правок, ошибки или конкретного оставшегося расхождения;
уже подтверждённые участки без затронувших их изменений повторно не проверять.
