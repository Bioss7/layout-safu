# Страницы и работа с проектом

Vite + pnpm. Страница: <page>/index.html, src/scss/<page>/, src/js/<page>/, public/<page>/assets/. У каждой свои стили, шрифты, изображения и авторский JS. HTML, PHP и данные сборка не генерирует. Готовые header/footer копируются с изменением только копий.

- Границы задачи: PHP, сервер, импорт ресурсов в Битрикс, деплой и другие страницы не менять без явного разрешения пользователя. Сборка layout не означает разрешение на импорт. git add/commit/push — только по явному разрешению пользователя.
- SCSS: _vars.scss, _mixins.scss, _fonts.scss, reset.scss, blocks/, вход style.scss.
- JS: компоненты подключаются отдельными обычными <script defer>, каждый самостоятельно инициализируется после готовности DOM. Имена сборки имеют префикс страницы. Vendor подключается отдельно перед зависимым компонентом. Проверять отсутствие import/export и общих неявных чанков в production-скриптах; объединяющий page.js не использовать.
- Изображения: public/<page>/assets/img/<block>/; шрифты — assets/fonts/. Пути исходников абсолютные /<page>/assets/....
- Проверка: pnpm build, затем preview и браузерные проверки. Конфигурацию и package.json менять только в необходимом объёме запрошенной работы.
- Форматирование стилей: Prettier, 2 пробела, LF, 100 символов. pnpm format:styles форматирует исходные SCSS страницы и служебный CSS; pnpm format:styles:check проверяет их. pnpm build после Vite запускает format:css:build для читаемого CSS новых страниц и UI. При добавлении страницы расширять явные списки этих команд; CSS остальных страниц и минификацию JS не менять.
- /ui/ — реестр из ui/data/pages.json. После создания страницы добавить ссылку, честный статус, макет и замечания. Существование HTML не означает, что страница проверена.
- Замечания хранятся только в ui/data/remarks.json: ID, страница, блок, селектор, состояния, применённое базовое оформление и исходный файл. В SCSS нет комментариев-маркеров: HTML читает JSON через локальный обработчик, строка определяется по селектору.
- После исправления или согласования состояния удалить запись JSON. pnpm remarks:md генерирует Markdown для страниц с remarksReport в ui/data/pages.json; Markdown вручную не редактировать. Сборка проверяет данные и обновляет Markdown. В UI показывать только открытые замечания.
- ui/data/blocks.json — реестр самостоятельных БЭМ-компонентов. Новые (new) и перенесённые/адаптированные (existing) учитывать отдельно. Ключ — страница + ID блока; экземпляры, __element, --modifier, контейнеры и типографические классы не считать новыми компонентами. Для нового компонента сразу фиксировать страницу, дату YYYY-MM-DD по Asia/Tomsk, этап и ID задачи. Если исторические данные не подтверждены — null. После проверки полного списка страницы добавлять её в auditedPages. Непроверенные страницы — «Нет данных».

## Статистика без запросов к ИИ

В начале зарегистрировать только журнал текущего чата: node tools/ai-statistics.mjs --register <путь-к-jsonl> --page <page>. Старые и чужие сессии не сканировать. Пути остаются в игнорируемой .ai-statistics/; браузер получает только агрегаты.

Начало реализации: --phase implementation; перед проверками: --phase verification; в конце: node tools/ai-statistics.mjs. Планирование определяется режимом Plan журнала, неизвестный этап остаётся неизвестным. Если журнал недоступен — сообщить, не выдумывать данные. Финальная реплика попадёт при следующем обновлении.

В /ui/statistics/ кнопка обновляет отчёт через локальный сборщик без модели/MCP. Токены, вызовы MCP и лимит аккаунта различаются. Кэш — часть входных токенов, reasoning — часть выходных; не складывать их повторно. Токены отдельным MCP-вызовам не приписывать. Лимиты — только датированный снимок источника, иначе «Нет данных».
Единый источник агрегатов статистики — игнорируемый .ai-statistics/report.json; HTML не рассчитывает расход из Markdown. Счётчики блоков включаются в тот же отчёт из ui/data/blocks.json. Фильтры не должны выдавать неподтверждённую дату/этап за нулевое количество. Проверки: pnpm project:data:check и pnpm check:project-data.

Служебный UI, отчёты и кэш Figma не импортируются в Битрикс. Сырые журналы, переписка, команды, секреты и абсолютные пути журналов в репозиторий не попадают.

## Каталог компонентов

ui/data/blocks.json — единый источник компонентов: entries сохраняет учёт блоков страницы, необязательные purpose/files/reuseSource описывают назначение и исходники. reusableComponents хранит подтверждённые примеры для копирования и не участвует в статистических счётчиках. Перед новым блоком проверить каталог, скопировать подходящий компонент в ресурсы текущей страницы и адаптировать копию. После изменений обновить сведения и проверить пути командой pnpm project:data:check.

Для расхождений текста/геометрии в remarks.json допускается description вместо перечня отсутствующих состояний; states остаётся пустым. HTML и Markdown показывают это как расхождение, не как отсутствующий hover.
