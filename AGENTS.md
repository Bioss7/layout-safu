# layout-safu — правила вёрстки

## Границы и порядок работы

- Самостоятельный Git-репозиторий; все исходники, ресурсы, инструменты и документацию вёрстки вести здесь. Описание и команды — в [README.md](README.md). В составе safu-dev-bus соблюдать [корневые границы и делегирование](../AGENTS.md); проверять состояние и diff обоих репозиториев отдельно.
- Перед работой кратко обозначить задачу и выбрать только нужные инструкции ниже. Не читать все навыки и большие файлы целиком без необходимости; node_modules/ и dist/ не исследовать как исходники.
- Менять только назначенную страницу и её ресурсы. Страницы независимы: готовый блок копировать и адаптировать, исходную страницу не менять. Шапку и подвал, включая общие стили, менять только по прямому указанию; старые страницы целиком не рефакторить вне задачи.
- Семантический HTML, БЭМ и Vanilla JavaScript. Основная раскладка — Flexbox; Grid допустим для простых компонентов или при явной необходимости двумерной сетки по [правилам SCSS](.agents/skills/scss-architecture/SKILL.md). Для одного варианта изображения — img, для вариантов по медиазапросам — picture по [правилам HTML](.agents/skills/bem-component/SKILL.md). Компонентные стили, состояния и адаптивы хранить вместе.
- Новые разрешения не требуют переписывать существующие компоненты вне задачи. Один агент может совмещать роли; разделение файлов и передача результатов через координатора обязательны при делегировании.
- Проверять требования, реестр компонентов, локальный код и ресурсы только в затронутой области. Для реализации по Figma читать `figma-mcp` и доступный `figma-design-to-code`; использовать подтверждённый кэш, не придумывать отсутствующий дизайн и существенное поведение. Документ Figma без указания пользователя не изменять.
- Проверки изменённого интерфейса выполнять по `interface-review`. Повторять только после новых правок, ошибки или конкретного непроверенного расхождения; для документации сборка не нужна.

## Условия готовности вёрстки по Figma

- Задача включает подтверждение точных данных макета, реализацию, измерение результата в браузере и визуальное сравнение. Написанный код или успешная сборка сами по себе не означают готовность.
- До сдачи самостоятельно исправить найденные расхождения в пределах задачи. Первичную сверку макета и вёрстки не перекладывать на пользователя; соблюдать существующие границы разрешённых изменений.
- Проверку выполнять по [interface-review](.agents/skills/interface-review/SKILL.md), источники и ресурсы подтверждать по [figma-mcp](.agents/skills/figma-mcp/SKILL.md). В результате назвать проверенные блоки, ширины и состояния, дать пути к сравнительным снимкам и указать оставшиеся ограничения.
- Если сравнение не выполнено, прямо написать «визуальная сверка не выполнена». Не заявлять о соответствии макету на основании неполных проверок.
