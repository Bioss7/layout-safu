# Graphify при создании страниц

Читать перед созданием новой страницы и подбором компонентов для неё.
Graphify — необязательный помощник: наличие скилла, CLI и локального графа
зависит от окружения разработчика. Репозиторий не устанавливает их автоматически.

## Проверка доступности

1. Проверить, есть ли `graphify` среди доступных скиллов текущего агента.
   Если есть — прочитать его `SKILL.md` по пути из списка скиллов; не использовать
   путь профиля другого разработчика.
2. Проверить наличие `graphify-out/graph.json` относительно корня `layout-safu/`.
   Каталог игнорируется Git и может отсутствовать после клонирования.
3. Для запросов использовать доступный CLI `graphify` из PATH или обнаруженного
   локального окружения. `.graphify_python` — только подсказка о расположении
   интерпретатора: перед использованием проверить, что путь существует.

Если скилл, CLI или граф недоступен либо запрос завершился ошибкой, продолжить
обычный поиск по `ui/data/blocks.json` и существующим страницам. Кратко отметить
ограничение в результате задачи. Не устанавливать зависимости, не создавать граф
и не менять конфигурацию агента только ради выполнения этой инструкции.

## Перед реализацией

- Сформулировать запросы по нужным блокам: где есть аналог, какие HTML/SCSS/JS
  составляют его реализацию, где документирован источник адаптации и какие
  проверки предусмотрены для страницы-аналога.
- Подобрать слова запроса из фактических названий узлов графа по скиллу;
  CLI сам не переводит русские формулировки в английские имена компонентов.
  Запускать запросы из `layout-safu/`, читать только относящиеся к задаче связи.
  Примеры команд и устройство этой карты — в [GRAPHIFY.md](../GRAPHIFY.md).
- Сверить найденное с `reusableComponents`, `entries`, `files` и `reuseSource`
  в `ui/data/blocks.json`, затем прочитать конкретные исходники аналога.
  Отсутствие узла в графе не доказывает отсутствие компонента в проекте.
- Если задача явно затрагивает общие ресурсы, определить связанные страницы и
  проверки. Найденная зависимость не даёт разрешения менять общую шапку или подвал.
- В документации новой страницы указать выбранный аналог и источник адаптации;
  реестры обновлять по обычным правилам проекта.

## Актуальность и границы

Граф — снимок исходников. Проверять актуальные файлы и реестр, особенно если они
изменились после построения карты. `INFERRED` и совпадения имён классов — подсказки,
а не подтверждение поведения; исторические аудиты не заменяют текущие проверки.
Если граф устарел, использовать подтверждённые сведения и обычный поиск, явно
отмечая ограничение; пересборка не обязательна для создания страницы.

Не перестраивать граф автоматически при каждой странице. При отдельной задаче
на обновление следовать `GRAPHIFY.md`: эта карта использует
`tools/graphify-map.py`, а обычный `graphify extract`/`--update` может потерять
дополнительные связи HTML, SCSS и реестра. Не запускать хуки, облачные сервисы,
импорт ресурсов или деплой. Анализ ограничен `layout-safu/` и `.graphifyignore`;
PHP, архивы и приватные данные остаются вне этой процедуры.
