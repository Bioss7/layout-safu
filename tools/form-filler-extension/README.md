# Формы — русские тестовые данные

Локальное расширение Chrome Manifest V3. Выбирает форму или область страницы,
заполняет её русскими тестовыми данными и позволяет обучать кастомные компоненты
кликами. Сервер, аккаунт, ИИ и сборка расширения не нужны.

## Установка

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение**.
3. Выберите именно каталог `layout-safu/tools/form-filler-extension`, содержащий
   `manifest.json`.
4. Закрепите расширение на панели Chrome. На обычной http(s)-странице нажмите его
   значок или **Alt+Shift+F**. Сочетание можно изменить в `chrome://extensions/shortcuts`.

Расширение запрашивает только `activeTab`, `scripting`, `storage`. Доступ к странице
выдаётся при запуске пользователем. Автоматического запуска при открытии сайта нет.
После перехода или перезагрузки нажмите значок ещё раз. Повторное нажатие скрывает
или показывает существующую панель без повторного подключения обработчиков.
После обновления файлов нажмите **Обновить** у расширения в Chrome, затем
перезагрузите тестируемую страницу.

## Заполнение

1. Нажмите **Выбрать форму** и кликните внутри нужной формы. Для произвольной
   обёртки используйте **Указать контейнер**; для части страницы — **Выделить область**.
2. Проверьте список найденных полей, их назначение и источник обработки.
3. При необходимости измените назначение, задайте **Постоянное значение** либо
   **Пропустить**. Для вариантов указывайте точный текст или значение; в
   мультиселекте разделяйте варианты символом `|`.
4. Для checkbox явно выберите **Отметить**, если отметка нужна. По умолчанию
   расширение не включает согласия. В radio выбирается первый доступный вариант
   либо вариант с заданным текстом/значением.
5. Нажмите **Заполнить выбранное** и проверьте отчёт. Расширение не нажимает
   кнопку отправки и не вызывает `submit()`.

При наведении во время выбора видны границы элемента. **↑** поднимает выбор к
родителю DOM, **↓** возвращает к предыдущему дочернему элементу, **Enter** подтверждает
выбор, **Escape** отменяет. Это полезно, когда контейнер полностью занят пунктами
списка. Кнопка **⇆** переносит панель налево/направо, **−** сворачивает её.

В прямоугольник включаются элементы, центры видимых управляющих частей которых
попали внутрь. Координаты учитывают прокрутку страницы. Radio объединяются по
`name` и владельцу формы; выбранный вариант за пределами области сохраняется.

**Только пустые поля** включено по умолчанию. Непустые поля, выбранные radio/select
и отмеченные checkbox сохраняются. Чтобы заменить их, снимите этот флаг.
Для нативного select пункт с непустым `value`, выбранный браузером по умолчанию,
считается уже заполненным.

Есть три повторяемых набора согласованных ФИО, тестовых email на `example.com`,
телефонов `+7`, русских адресов и текстов. Один набор даёт одинаковые значения
в обоих режимах; число и дата учитывают ограничения поля. Телефонные маски
обрабатываются событиями `input`/`change` самого сайта. Непройденная браузерная
валидация и `aria-invalid="true"` отображаются как ошибка, а не как успех.
Неочевидный текст требует проверки назначения. Бизнес-правила сайта автоматически
не выводятся. Повторный поиск пересоздаёт список полей и его временные настройки.

## Сравнение двух вариантов на САФУ

### Вариант 1: готовые правила

1. Откройте страницу мероприятий `/events/` или программ `/programs/`.
2. Оставьте режим **Готовые правила / Авто** и включите **Правила САФУ на этом сайте**.
   Разрешение набора хранится отдельно для каждого origin, включая порт localhost.
3. Выберите форму и набор **1 · Иванов Алексей Сергеевич**.
4. У селекта должен появиться источник **Правило САФУ**. Заполните форму, проверьте
   подпись, выбранные пункты и связанные значения через DevTools при необходимости.

Поддерживаются реальные семейства `.js-topic` (мероприятия, абитуриенты,
мультиселекты фильтров) и `[data-topic]` (программы). Нативные checkbox со стилизацией
остаются нативными. Отдельный выдуманный адаптер кастомных radio САФУ не добавлен:
в проверенной разметке такого компонента нет. Заполнение использует клики
компонентов, не демонстрационное меню сайта.

### Вариант 2: обучение с нуля

1. Перезагрузите ту же страницу, заново откройте расширение и выберите режим
   **Проверка обучения**. Готовые адаптеры САФУ и общее распознавание кастомных
   компонентов в этом режиме отключены; нативные поля продолжают работать.
2. При необходимости откройте **Сохранённые правила** и очистите учебный набор.
3. Выберите форму. Кастомный селект пока должен показывать **Нужно обучение**.
4. Выберите тип **Селект**, нажмите **Указать и обучить** и пройдите мастер:
   управляющая кнопка → открытие → контейнер списка → пример пункта →
   подтверждение подсвеченных вариантов → пробный выбор → сохранение.
5. Для мультиселекта заранее выберите тип **Мультиселект**. Для radio укажите
   контейнер всей группы и пример варианта; для checkbox — переключатель.
6. Перезагрузите страницу, откройте расширение и снова выберите ту же форму.
   Источник должен стать **Обучение**, без **Правило САФУ** и **Автораспознавание**.
7. Заполните тем же набором 1. Сравните значения и видимые состояния с вариантом 1.

Пробный выбор во время обучения меняет состояние компонента на странице. Для
чистого сравнения нужна перезагрузка. Если предложенные варианты неверны,
отмените мастер и выберите более точный контейнер/пункт. В обычном режиме
пользовательские правила имеют приоритет перед встроенными, затем применяется
общее распознавание по ARIA.

## Правила и хранение

Обычный и учебный наборы независимы. Очистка учебного набора удаляет только
учебные правила текущего origin, сохраняя обычные правила и настройки.
В разделе **Сохранённые правила** можно просмотреть и удалить правило, получить
JSON для копирования или импортировать JSON текущего набора для этого сайта.
Для переноса с localhost на другой origin измените `origin` в экспортированном JSON
осознанно перед импортом; чужие origin при импорте отклоняются.

В `chrome.storage.local` сохраняются настройки режимов и декларативные правила
версии 1: origin, точный pathname без query/hash, тип компонента, уникальный
CSS-локатор кнопки/группы, локатор списка, селектор однотипных вариантов и признак
выбора (`aria-selected`, `aria-checked`, `data-state`, `checked` или CSS-класс).
Значения форм, постоянные значения из панели и отчёты не сохраняются.
Не используются координаты кликов, произвольный JS, eval или внешние запросы.

Один адаптер обслуживает встроенные и обученные правила: `open()`, `options()`,
`read()`, `apply()`, `close()`. При отсутствии или неоднозначности локатора правило
выдаёт ошибку и требует повторного обучения. Уникальные локаторы строятся по id,
атрибутам и устойчивым классам, без `nth-child`. Одинаковые элементы без
различимого контейнера могут потребовать изменений доступности на самом сайте.

## Ограничения первой версии

- iframe, закрытый Shadow DOM, сложные календари, виртуализированные списки,
  CAPTCHA, пароли, файлы и автоматическое прохождение многошаговых форм исключены.
- Скрытые технические, disabled, readonly и inert поля не заполняются. Скрытый
  нативный checkbox/radio со стилизацией доступен через видимую связанную подпись.
- Поддерживаются вынесенные в `body` и пересоздаваемые списки, если выбор можно
  подтвердить после открытия. Если компонент не предоставляет наблюдаемого
  состояния, мастер откажет в сохранении правила.
- Для сложных виджетов, игнорирующих программные события (`isTrusted`), заполнение
  может не работать. Неуспешные действия отмечаются в отчёте.
- Кнопки submit/reset и ссылки не принимаются как безопасные переключатели.
  Кастомные обработчики самого сайта продолжают работать при изменении полей.
- `chrome://`, магазин Chrome и другие защищённые страницы недоступны. Ошибка
  запуска отмечается значком `!` и подсказкой на кнопке расширения.

## Проверки разработчика

Из корня `layout-safu`:

```powershell
node --test tools/form-filler-extension/tests/core.test.mjs
node --test tools/form-filler-extension/tests/browser.test.mjs
```

Браузерный тест использует установленный в проекте `@playwright/test` и его Chromium.
Если браузер ещё не установлен: `pnpm exec playwright install chromium`.
Тест создаёт временный профиль и копию расширения с доступом только к своему
localhost: это заменяет ручное нажатие значка, которое Playwright не предоставляет.
Рабочий manifest остаётся без `host_permissions`. Тестовый сервер останавливается,
временный профиль удаляется после проверки.

Проверяются реальные HTML/JS форм мероприятий и программ, одинаковый результат
готового и обученного селекта, мультиселект, независимые компоненты без ARIA,
radio/checkbox, динамический портал, маска, события, перезагрузка, область,
отмена, импорт, изоляция наборов, неактуальные локаторы и панель на 390px.
Для реальных страниц стенд добавляет минимальный CSS, не меняя исходники:
это функциональная проверка, а не визуальная сверка сайта с макетом.
Переменная `SAFU_FILLER_SCREENSHOTS` задаёт внешний каталог снимков панели.
