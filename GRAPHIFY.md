# Локальная карта layout-safu

Первый проход: 2026-10-30. Graphify 0.9.97, Python 3.14, отдельное окружение
`%USERPROFILE%\.codex\tools\graphify`. Область анализа — только этот репозиторий.

## Результат и проверка

- 269 текстовых файлов: 150 SCSS, 63 JS/MJS, 29 Markdown, 15 HTML, 11 JSON, 1 CSS.
- 629 узлов, 1 567 связей, 41 сообщество. Все входные файлы представлены в графе.
- Документация прочитана полностью: 29 файлов, 1 674 строки. Исторические результаты
  аудитов не считаются результатами сегодняшнего запуска.
- JSON читается, конечные узлы всех экспортированных связей существуют, пути
  исходников разрешаются. Висячих локальных ссылок и неразрешённых SCSS-импортов нет.
- Четыре самоссылки — рекурсивные вызовы обхода файлов, а не потерянные зависимости.
- HTML проверен в Chrome через Playwright: canvas отображается, ошибок JavaScript
  и неудачных запросов нет. Библиотека vis-network сохранена рядом с HTML и проверена
  по SHA-384 из экспорта Graphify; браузеру не нужен CDN.
- Внешние модельные API не использовались. Точный расход токенов агентов недоступен;
  это не означает нулевой расход модели.

## 1. Где искать аналоги компонентов

Начинать с [реестра блоков](ui/data/blocks.json): `reusableComponents` содержит
подтверждённые примеры, `purpose` — назначение, `files` — исходники,
`reuseSource` — документированный источник адаптации. `entries` дополняет карту
экземплярами на страницах; `auditedPages` задаёт полноту учёта, а не качество вёрстки.

Практические примеры из реестра, найденные также запросом к графу:

- `abiturient / review-card`: [разметка](abiturient/index.html),
  [стили](abiturient/assets/scss/blocks/reviews.scss),
  [поведение](abiturient/assets/js/reviews.js). Источник адаптации — `main / review-card`:
  [главная](index.html), [исходные стили](main/assets/scss/blocks/review.scss).
- `abiturient / button`: [базовые стили](abiturient/assets/scss/blocks/button.scss);
  дополнительные файлы состояний и контекстов перечислены в `files` реестра.
- `abiturient / education-card`, `study-card`, `feature-card`, `card-arrow` и
  `link-arrow` — другие зарегистрированные примеры для поиска перед новой вёрсткой.

Связь `documented_reuse_source` подтверждает запись в реестре, но не идентичность
текущего кода. Копировать и сверять следует весь комплект HTML, SCSS, JS, ресурсов,
адаптивов и состояний по правилам [AGENTS.md](AGENTS.md).

## 2. Что затрагивает общая оболочка

[tools/page-assets.mjs](tools/page-assets.mjs) раскрывает маркеры `safu:header` и
`safu:footer` из [header.html](assets/html/header.html) и
[footer.html](assets/html/footer.html). [common.scss](assets/scss/common.scss)
подключает стили шапки, панелей, поискового поля, подвала и общего каркаса.
Поведение находится в [header.js](assets/js/header.js) и [footer.js](assets/js/footer.js).

Оба маркера обнаружены в 12 страницах:
главная, `abiturient`, `about`, `partners`, `programs`, `programs/detail`,
`schoolchildren`, `stp`, `students`, `template-abiturient`,
`template-international`, `template-main`.

Это исходный список проверки при разрешённом изменении общей оболочки. Сам граф
не доказывает одинаковый внешний вид всех страниц: модификаторы и состояния нужно
проверять отдельно. Связи с действующим PHP-шаблоном в этот проход не входят.

## 3. Какие проверки предусмотрены для abiturient

| Проверка | Назначение |
| --- | --- |
| `pnpm check:abiturient` | Основной браузерный сценарий: подключения ресурсов, адаптивы, формы, FAQ, слайдер, диалог, оболочка, управление с клавиатуры и касаниями |
| `pnpm check:typography` | Типографика по локальному JSON-эталону, загрузка шрифтов и отдельные hover-состояния |
| `node tools/check-abiturient-alignment.mjs` | Геометрия; есть известное ограничение округлённых накопленных координат |
| `node tools/check-abiturient-adaptives.mjs` и остальные `check-abiturient-*.mjs` | Дополнительные сценарии для адаптивов и отдельных ширин; условия запуска смотреть в конкретном инструменте |
| `pnpm project:data:check`, `pnpm check:project-data` | Согласованность реестров, путей и обработчика проектных данных |
| `pnpm check:assets` | Проверки обработки ресурсов; дополнительные браузерные команды перечислены в package.json |

Браузерным проверкам страницы нужен обслуживаемый сайт; основной сценарий ожидает
собранный preview по `http://127.0.0.1:4173`, адрес меняется через
`ABITURIENT_BASE_URL`. В этой задаче сборка, preview и проверки самого интерфейса
abiturient **не запускались**. Исторические успешные аудиты требуют актуальной перепроверки.
Ограничение геометрии описано в [.agents/project.md](.agents/project.md): зелёный
результат скрипта не заменяет визуальную сверку с Figma.

## Использование

В PowerShell из `layout-safu/`:

```powershell
$graphifyCli = Join-Path $env:USERPROFILE '.codex\tools\graphify\Scripts\graphify.exe'
& $graphifyCli query 'button review card' --budget 12000
& $graphifyCli query 'header footer common' --budget 12000
& $graphifyCli query 'abiturient typography alignment check' --budget 12000
```

Это проверенные расширения трёх вопросов словами из словаря графа. Полные ответы
сохранены в `graphify-out/query-reuse.txt`, `query-impact.txt`, `query-checks.txt`;
результаты не усечены. При новых формулировках скилл сначала подбирает слова из
фактических названий узлов: CLI не переводит русский запрос в английские имена автоматически.

Для повторения структурного прохода и сборки с существующими семантическими фрагментами:

```powershell
$graphifyPython = Join-Path $env:USERPROFILE '.codex\tools\graphify\Scripts\python.exe'
& $graphifyPython tools/graphify-map.py prepare
& $graphifyPython tools/graphify-map.py build
```

Адаптер [tools/graphify-map.py](tools/graphify-map.py) дополняет AST связями HTML,
SCSS, реестра и npm-команд. Если Markdown изменился, сборка остановится по хешам:
нужно заново получить семантические фрагменты через скилл Graphify, затем удалить
только прежний `graphify-out/.graphify_semantic_sources.json` и повторить сборку.
После удаления `graphify-out/` семантический проход также потребуется заново.
`--force` допустим только при проверенном намеренном уменьшении графа.

Обычный `graphify extract`/`--update` не вызывает этот адаптер и может потерять
дополнительные связи вёрстки; для этой карты использовать описанную последовательность.

## Ограничения

`EXTRACTED` — явная ссылка, импорт, маркер или запись реестра; `INFERRED` — вывод,
например совпадение имён классов. Совпадение не подтверждает выполнение обработчика
или применение стиля. Вложенные SCSS-селекторы, вычисляемые строки JS, динамический
DOM и каскад целиком этим проходом не моделируются. Копии компонентов не объединяются
только из-за одинакового имени.

Граф неориентированный; исходные направления и несколько доказательств для одной
пары сохранены в `evidence_records`. Внешние зависимости представлены ссылочными
узлами без чтения библиотек. Автоматические сообщества — навигационная эвристика,
а не утверждение об архитектуре; их названия могут повторяться.

Изображения, шрифты, vendor, сборка, зависимости, журналы, приватная статистика,
lock-файлы и PHP исключены. Внешние Figma-ссылки из документации не загружались.
Документы содержат расхождения разных дат: ранние упоминания единого JS-бандла и
разные исторические объёмы типографических проверок не являются текущим контрактом.
Исходники страниц и родительский репозиторий не изменялись; импорт, деплой и Git-коммиты
не выполнялись.
