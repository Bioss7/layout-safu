# САФУ — исходная вёрстка

Самостоятельный проект на Vite и pnpm для HTML-страниц, компонентных SCSS, JavaScript и локальных ресурсов сайта САФУ. Здесь ведутся все работы с вёрсткой, адаптивами, поведением интерфейса и документацией этих работ.

Это отдельный Git-репозиторий: `https://github.com/Bioss7/layout-safu.git`. При размещении внутри `safu-dev-bus/layout-safu/` он сохраняет собственную историю; состояние и изменения Git нужно проверять отдельно от основного проекта.

## Запуск и сборка

Требуются Node.js 22+ и pnpm. Все команды ниже выполняются из папки `layout-safu/`.

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

`pnpm dev` запускает Vite с HMR для исходной вёрстки. PHP и Битрикс в этом режиме не выполняются.

```sh
pnpm build
pnpm preview --port 4173
```

Сборка проверяет проектные данные, обновляет Markdown замечаний из реестра, собирает проект в `dist/` и форматирует перечисленные в конфигурации итоговые CSS. Preview позволяет проверить собранные страницы в браузере. Обновление Markdown может изменить отслеживаемые файлы — после сборки проверьте diff.

## Форматирование при сохранении

При работающем `pnpm dev` Vite автоматически форматирует сохранённые и новые HTML, SCSS, CSS, JavaScript и JSON локальным Prettier. Это работает из любого редактора и при изменении файлов внешними инструментами. Форматируется только изменённый файл; запуск сервера не форматирует существующие файлы. Ошибки синтаксиса выводятся в терминал без перезаписи файла; после исправления форматирование продолжится при следующем сохранении.

Для форматирования без запущенного Vite откройте `layout-safu/` отдельным окном VS Code (`code layout-safu` из родительского проекта) и используйте рекомендованное расширение **Prettier – Code formatter** (`esbenp.prettier-vscode`). Настройки папки включают форматирование при сохранении тех же типов файлов. При открытии только родительской папки вложенные настройки `.vscode/` не применяются. Сначала установите зависимости командой выше.

Параметры берутся из `.prettierrc.json`: 2 пробела, LF, ширина 100 символов. `.prettierignore` исключает сборку, зависимости, кэш Figma, приватную статистику, снимки, результаты тестов и сторонние библиотеки. Команда `format:css:build` использует отдельный `.prettierignore.build`, чтобы явно перечисленный итоговый CSS продолжал форматироваться.

Vite обновляет страницу при сохранении, включая запись форматтера. Повторное событие не вызывает бесконечных записей: уже отформатированный текст не перезаписывается. Сохранение не запускает сборку или импорт; при `pnpm build` и `pnpm preview` автоформатирование исходников отключено.

## Структура и ресурсы

| Путь | Назначение |
| --- | --- |
| `index.html`, `<page>/index.html` | Главная и остальные HTML-страницы |
| `<page>/assets/scss/` | Стили страницы: `<page>.scss`, переменные, миксины, reset и `blocks/` |
| `<page>/assets/js/` | JavaScript компонентов страницы |
| `<page>/assets/img/`, `<page>/assets/fonts/` | Изображения и специфичные шрифты страницы |
| `assets/html/`, `assets/scss/`, `assets/js/` | Единый источник общей шапки, панелей меню/поиска и подвала |
| `assets/img/`, `assets/fonts/`, `assets/vendor/` | Общие изображения, шрифты и локальные сторонние библиотеки |
| `ui/` | Служебный интерфейс и реестры страниц, компонентов и замечаний |
| `tools/` | Инструменты проверок и обслуживания проекта |
| `dist/` | Результат сборки, исключённый из Git |

Страницы независимы: стили, авторские скрипты и ресурсы хранятся по страницам. Готовый блок копируется и адаптируется для новой страницы; изменения копии не должны затрагивать исходную. Компонентные стили, состояния и адаптивы хранятся вместе. Правила реализации — в [AGENTS.md](AGENTS.md) и профильных инструкциях по ссылкам из него.

HTML явно подключает стили и отдельные обычные defer-скрипты. Общая разметка включается маркерами `<!-- safu:header -->` и `<!-- safu:footer -->`; Vite раскрывает их в dev и build. Главная сохраняет корневой `index.html`, её ресурсы находятся в `main/assets/`. Каталог и детальная программа используют ресурсы раздела `programs`.

Vite собирает CSS и JS в `dist/<page>/assets/css/` и `dist/<page>/assets/js/`, общую оболочку — в `dist/assets/`. Изображения, шрифты и vendor сохраняют свои каталоги, включая динамически выбираемые ресурсы. Исходные SCSS и HTML-фрагменты в dist не копируются. В SCSS используются относительные `@use` и `url()`; ссылки сборки работают во вложенном каталоге. Библиотеки хранятся в одном месте и подключаются только там, где нужны.

Общая шапка основана на внутренних страницах, подвал — на абитуриенте. На главной, странице абитуриента и студентов используется модификатор `.header--overlay`. Новые различия добавляются модификаторами общего компонента. При добавлении страницы нужно согласовать владельцев ресурсов в `tools/page-assets.mjs`, входы сборки, списки форматирования и реестры по [.agents/project.md](.agents/project.md).

`pnpm check:assets` проверяет структуру dist, ссылки и самодостаточность скриптов. `pnpm check:assets:browser` проверяет страницы через preview на семи ширинах; для сравнения содержимого сначала сохранить исходную проверку с `--baseline`. Результаты и снимки находятся в `screenshots/asset-migration/` и не входят в Git.

`pnpm check:assets:runtime` проверяет взаимодействия в preview (4173), dev (5174) и preview с `--base /nested/` (4175); серверы нужно запустить заранее. Список адресов можно передать в `ASSETS_TEST_URLS` через запятую. `pnpm check:assets:panel` проверяет локальную имитацию панели Битрикс на preview 4173 без обращения к серверу.

## Проверки и инструменты

| Команда | Назначение |
| --- | --- |
| `pnpm project:data:check` | Проверить реестры и пути компонентов |
| `pnpm check:project-data` | Выполнить тесты обработки проектных данных |
| `pnpm check:format-on-save` | Проверить автоформатирование Vite, исключения и восстановление после ошибки |
| `pnpm format:styles:check` | Проверить форматирование явно перечисленных исходных стилей |
| `pnpm format:styles` | Отформатировать эти стили с изменением файлов |
| `pnpm remarks:md` | Обновить Markdown из реестра замечаний |
| `pnpm check:abiturient` | Проверить интерфейс страницы абитуриента в браузере |
| `pnpm check:typography` | Проверить типографику страницы абитуриента по сохранённым данным Figma |
| `pnpm webp` | Запустить ручную конвертацию PNG в WebP |
| `pnpm optimize` | Запустить ручную оптимизацию изображений |

Браузерные проверки запускаются после сборки при работающем preview на `http://127.0.0.1:4173`; другой адрес задаётся через `ABITURIENT_BASE_URL`. Они используют Playwright: на Windows нужен установленный Chrome, на других платформах — Chromium для Playwright (`pnpm exec playwright install chromium`). Проверки относятся к конкретной странице и не заменяют проверку остальных изменённых страниц и их адаптивов. `pnpm test` сейчас является заглушкой.

Учёт статистики запускается только по отдельному запросу: правила и команды описаны в [.agents/statistics.md](.agents/statistics.md).

## Передача в Битрикс

`pnpm build` создаёт результат в `dist/` и не импортирует его в Битрикс. Ресурсы переносятся отдельными командами основного проекта, а PHP-разметка адаптируется вручную. Служебные страницы, отчёты и кэш Figma не импортируются.

В составе `safu-dev-bus` см. [основной README](../README.md#интеграция-в-битрикс) и [правила интеграции](../AGENTS.md#интеграция-в-битрикс). Импорт, изменения PHP, сервер и деплой требуют явного разрешения пользователя. Импортированные ресурсы следует исправлять в исходниках этого проекта.
