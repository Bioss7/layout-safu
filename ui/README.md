# Служебный каталог

`/ui/` — ссылки на страницы и открытые замечания из `ui/data/remarks.json`.
`/ui/statistics/` — агрегаты зарегистрированных журналов Codex и реестр БЭМ-компонентов.

Запуск: `pnpm build`, затем `pnpm preview --host 127.0.0.1 --port 4173`.
Кнопка «Обновить статистику» вызывает только локальный Node.js-обработчик. Модель,
Figma и другие внешние API не вызываются. Наблюдателя за журналами нет.

Регистрация **только текущего чата**, без поиска по истории:

```powershell
pnpm stats --register <полный-путь-к-журналу.jsonl> --page abiturient --phase implementation
pnpm stats --phase verification
pnpm stats
```

В начале следующей задачи зарегистрировать её текущий журнал/страницу. В конце
обновить отчёт. После финального ответа кнопка прочитает и последнюю запись.
Реестр источников, отметки этапов и отчёт находятся в игнорируемой `.ai-statistics/`.
Журналы не копируются. В браузер поступают только суммы по задачам и этапам.

Ответы считаются по `response_id`, завершённые MCP — по ID инструмента, включая
ошибки. Накопительные счётчики не суммируются. Кэш включён во входные токены,
reasoning — в выходные. Отсутствующие показатели остаются «Нет данных».
Время включает инструменты/ожидание внутри рабочего хода; паузы между ходами
исключены. Прерванные ходы заканчиваются по `turn_aborted`.

Лимиты берутся из последнего доступного `token_count.rate_limits` зарегистрированных
журналов с датой и источником. Это сохранённый снимок, не текущий ответ API.
Дополнительный подтверждённый снимок можно сохранить в `.ai-statistics/account-limits.json`:

```json
{"capturedAt":"<ISO-дата>","source":"<подтверждённый источник>","windows":[{"name":"<окно>","usedPercent":null,"resetsAt":null}]}
```

Сборщик не запрашивает API лимитов аккаунта. Без подтверждённого снимка показывает
«Нет данных». Из общего процента расход страницы не вычисляется.

Новые страницы добавляются в `ui/data/pages.json`. Ссылки на неизвестные макеты
оставляются `null`. Замечания редактируются только в `ui/data/remarks.json`.
В SCSS остаются ссылки по ID; номера строк определяются при чтении данных.
`pnpm remarks:md` генерирует Markdown для страниц с полем `remarksReport` в реестре
страниц. Его не редактируют вручную. `pnpm build` проверяет реестры и обновляет Markdown.
Весь `dist/ui/` исключён из импорта в Битрикс. Private JSON, эталоны Figma и исходные
фотографии кэша не входят в сборку. Без локального preview статистика недоступна.

Проверки: `pnpm check:statistics`, `node tools/check-ui.mjs` при запущенном preview.

## Блоки вёрстки

Единый реестр — `ui/data/blocks.json`. Самостоятельный БЭМ-компонент считается один
раз на страницу. Повторные карточки, элементы `__element`, модификаторы `--modifier`
и структурные обёртки не увеличивают число. Новые компоненты и готовые, перенесённые
или адаптированные, показаны отдельно. Происхождение фиксируется при проверке кода,
а не выводится из совпадения имён CSS-классов.

Начальная инвентаризация выполнена для «Абитуриента»: 21 новый и 10 перенесённых
компонентов. Для остальных страниц происхождение пока не подтверждено: «Нет данных».
При создании нового блока добавить запись с `id`, `name`, `page`, `origin`,
`addedAt` (YYYY-MM-DD по Asia/Tomsk), `phase` и `taskId`. `auditedPages` содержит
только страницы с проверенным полным перечнем. У исходной инвентаризации дата,
этап и задача неизвестны (`null`); фильтры не выдают их за ноль.

Статистика хранится в `.ai-statistics/report.json`; Markdown для её чтения не нужен.
Сборщик добавляет реестр блоков в этот JSON без модели, Figma и внешних API.
Проверки реестров: `pnpm project:data:check` и `pnpm check:project-data`.
